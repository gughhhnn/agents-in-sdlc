GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、作業がローカルマシンでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐次確認できます。差分を確認して変更ごとに受け入れまたは却下し、フォローアップのプロンプトで会話を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集を確認して受け入れます。
- セッション中にエージェントへ指示し、ハイコントラストモードに加えてライトモードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードへの切り替えも追加したいとのことです。新しい会話を最初から始めずに、既存のセッションに指示して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各ステップ、調査するファイル、実行するコマンド、提案する編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. ファイル編集が提案されると、差分がチャット内に表示されます。
   - **Keep** を選ぶと変更を受け入れます。
   - **Undo** を選ぶと変更を元に戻し、もう一度作業するようエージェントに依頼します。
4. チャットの上部にある **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> (ターミナルコマンドの実行など) ツールの使用許可を求められると、エージェントは一時停止して **Allow** の確認を表示します。自分が許可できるコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキスト (変更したコンポーネント、スタイルの方法、設定した local storage のパターンなど) を保持しています。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    いいですね。次はハイコントラスト切り替えと並べて、ライトモードの切り替えを追加してください。ライトモードも同じパターンに従い、local storage に保存して、同じ UI から選べるようにしてください。ユーザーがハイコントラストとライトモードを個別に有効にできるようにしてください。
    ```

2. エージェントは前回の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストの場合と同様に、新しい編集を確認し、変更ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、切り替え UI を意図しない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで作業を中止し、明確なフォローアップを送ります。

> [!TIP]
> 進行中のセッションに指示すると、最初からやり直すより早く作業できます。フォローアップで変更を依頼したり (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正したり (「切り替えボタンを3つにせず、ライトモードを既存の設定パネルに加えてください」)、範囲を広げたり (「両方の切り替えにキーボードショートカットも追加してください」) できます。

## 変更内容を確認する

作業をコミットする前に、エージェントが変更したファイルをひととおり確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティの指針に沿っていること、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持などを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して調整しました。各ファイルの編集が行われるたびに確認し、変更を受け入れるか却下するかを選び、コンテキストを保ったままフォローアップを送って作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイル編集を個別に受け入れ、または却下しました。
- 進行中のセッションに指示を追加し、作業を調整しました。

次のレッスンでは、[アクセシビリティ機能を PR として公開][next-lesson]し、演習中にローカルのカスタムエージェントが作成した変更を確認します。
