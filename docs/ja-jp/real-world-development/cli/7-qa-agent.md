これまでに `quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーからフィルタリングの動作を確認しました。次は、これらの機能を、明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次の操作を行います。

- カスタムエージェントがインストラクション、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成し、内容を確認します。
- QA エージェントを選択し、フィルタリング issue に照らして結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を開く前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザーでの動作を一貫して確認したいと考えています。カスタムエージェントを使うと、QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な構成です。プロファイルには、エージェントの目的、インストラクション、利用可能なツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズは、それぞれ役割が異なります。リポジトリのインストラクションはチームの標準を定義します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、これらの機能を使って要件を評価し、結果を報告する方法を Copilot に伝えます。既存の機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能 PR を開く前に、再利用可能な QA プロファイルを Copilot に作成してもらいます。プロファイルでは、QA が実施するチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のプロンプトで新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を issue と合意済みの要件に照らして確認し、リポジトリのインストラクションに従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、カバレッジが不足している場合はテストを追加してください。

   各要件について、根拠とともに pass、fail、blocked のいずれかで報告してください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしてはいけません。

   まずはプロファイルを作成するだけにして、内容を確認できるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の流れと制約をプロファイルに反映したことを確認します。これにより、未完成のエージェントや範囲が広すぎるエージェントが、検証だけを行うつもりなのに機能を変更することを防げます。

1. `/diff` を実行し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は任意ですが、含めるとエージェントの表示名を明確にできます。
3. プロファイルのインストラクションを読み、QA が要件を確認し、リポジトリのインストラクションに従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を報告し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を開いたりしないことを確認します。
5. これらの役割や制約が不足している場合は、続行する前に既定のエージェントに修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成したら、同じフィルタリングの会話を再開し、QA を選択して、会話に残っている issue と計画を使います。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成したばかりの場合、利用可能なエージェント一覧に表示されないことがあります。エージェントは存在しており、上記のコマンドで有効にできます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   issue と計画で決めた内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントが作業を始めます。
4. 完了したら、レポートを読みます。
