最初は小さな機能をプロジェクトに追加しました。しかし、大きな変更にはより確実なプロセスが必要です。GitHub Copilot CLI は既存の開発フローに沿って作業できるため、適切な方法で必要な機能を作れます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを体験します。issue を使って機能を作り、コードの妥当性と機能の動作を確認して、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能の作業を進める間は、同じ会話とブランチを使います。通常はファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主要な概念に集中できるよう、手順を簡略化しています。

このレッスンでは、次の操作を行います。

- GitHub issue から新しい Copilot の会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送したブラウザーで機能を手動で検証します。

機能の作業を続ける中で、リポジトリのインストラクションを更新し、既存の `quality-checks` スキルをカスタマイズし、MCP 検証を追加して QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のカタログは拡大しており、訪問者はカテゴリやパブリッシャーでゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておきたい詳細もあります。Plan モードで方針を決め、その後、範囲を限定した実装を Autopilot に任せます。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業を記述した issue から始めます。
2. 実装する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行して検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって詳細は異なりますが、ほとんどの場合は上記の流れを調整したものになります。

この標準的な手順に沿うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビュー工程を経るようにできます。

## 会話モード

**会話モード**は、エージェントがどこまで自律的に作業できるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクトファイルの編集はできません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から始める

フィルタリング機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージされていることを確認します。
3. まだターミナルを開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を2回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることに気付くでしょう。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) を会話のコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てると、機能やタスクを Copilot に任せる前に、実装方法を定義できます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装するための計画を作成してください。
   ```

Copilot が計画を作成します。最初にプロジェクトを調べて、最適な方法を検討します。

3. フィルタリングの動作について質問された場合は、希望に応じて回答します。正解はひとつではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 自分の決定と異なる箇所があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成して確認したので、次は実装です。Autopilot を使って Copilot に作業を任せましょう。

Autopilot では、Copilot が完了したと判断するまで、問題に対する作業を繰り返します。

1. **Accept plan and build on autopilot (recommended)**、またはインストールされているバージョンで同様の名前が付いた項目を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が合意した計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まる場合があります。最初に計画を確認してください。Copilot から依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決してください。

## 実装をレビューして検証する

他のコードと同じように、生成されたコードはマージ前にレビューする必要があります。コードを確認し、サイトを実行して問題がないか確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** または **Autopilot** が表示されていないことを確認します。
2. `/diff` を実行し、フィルタリングの実装とテストを確認します。
3. 結果を issue と計画中に決めた内容と比較します。
4. コードを確認したら、<kbd>Esc</kbd> を押して差分表示を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を試す

コードに問題がないことを確認できました。次はアプリが動くか確認しましょう。前回と同じようにアプリを起動し、Codespaces で転送したポートを使ってサイトを開きます。

1. Copilot に次のプロンプトを送り、アプリを起動してもらいます。

   ```plaintext
   ブラウザーでフィルタリング機能を試せるようにアプリを起動してください。URL を教えて、サーバーは実行したままにしてください。
   ```

2. Codespaces でポート `4321` が利用可能と表示されたら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリの絞り込み、パブリッシャーの絞り込み、組み合わせを試します。
4. リセット時と結果が空の場合の動作が、issue と合意内容に沿っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

- Autopilot モードで新しい機能を実装しました。
