Space Quiz を GitHub Pages にデプロイして、誰でもアクセスできるようにしましょう。Copilot はワークフローの準備とデプロイを支援しますが、変更をレビューし、サイトが公開されたことを確認するのはユーザー自身です。

このレッスンでは、次の操作を行います。

- GitHub Pages のデプロイを設定するよう Copilot に依頼します。
- ワークフローとプルリクエストをマージ前にレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、ユーザーが簡単に試す方法が必要です。単一ファイルで構成されたサイトを GitHub Pages に公開すると、サーバーやランタイム依存関係を追加せず、公開 URL から利用できるようになります。

## デプロイの準備を Copilot に依頼する

> [!WARNING]
> プルリクエストの作成では、コードのコミットとプッシュが行われることがあります。プロンプトを送る前に、承認設定と送信先のリポジトリを確認してください。**Approve all** を有効にしている場合、個別の確認は表示されないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリに GitHub Pages へのデプロイを準備してください。必要であれば Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README が存在しない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更でプルリクエストを作成し、そのリンクと、必要な Pages の設定や権限を報告してください。マージ、自動マージの有効化、Pages の設定変更、デプロイは行わないでください。レビューを待って停止してください。
```

## ワークフローとプルリクエストをレビューする

1. README は、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ビルドとデプロイの手順、トリガー、権限など、プルリクエストの変更を確認します。
3. ワークフローが未マージのプルリクエストではなく、既定のブランチからデプロイすることを確認します。
4. 修正が必要であれば依頼し、更新された差分を確認します。マージを許可する前に、必要なプルリクエストのチェックが合格するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送ると、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、これらの操作に別の確認が求められないことがあります。

`<PR_NUMBER>` をレビューしたプルリクエストの番号に置き換え、次のプロンプトを別途送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使って GitHub Pages を有効にし、必要なチェックが合格した後にそのプルリクエストのみをマージして、デプロイが成功するまで監視してください。公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージに必要な権限がない場合は、私が何を承認または実行する必要があるかを正確に説明してください。サイトが公開されるまで、成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプルリクエストのマージをできない場合は、エージェントの具体的な指示に従います。デプロイが成功し、公開サイトが読み込まれるまで、タスクが完了したと判断しないでください。
